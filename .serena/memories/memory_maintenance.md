# Обслуживание memories

## Модель discovery

- Агент стартует со списком имён memories. Вход в граф — `mem:core` (карта проекта); оттуда ссылки ведут к доменным memories, из них — к более частным. Глубина графа растёт вместе с проектом.
- Папки/топики группируют связанное (сейчас: `modules/*` зеркалит модули core).
- Ссылка — `mem:имя` в backtick'ах. Текст вокруг ссылки говорит, что там и когда её читать; сама memory не описывает условия своего чтения — это обязанность ссылающейся.

## Стиль

Плотные заметки для агента, не проза. Инварианты и краткие буллеты; контекст, обоснования и примеры — только там, где они предотвращают вероятную ошибку. Язык — русский (конвенция репо). Прогонять через skill `stop-slop`.

## Порог добавления

Добавлять и обновлять только стабильные неочевидные знания, экономящие повторное расследование. Не добавлять: быстро находимые по коду факты, общие знания языков/фреймворков, one-off заметки под задачу, volatile построчные детали, счётчики (количество тестов, строк).

## Memories — состояние, не хроника

Memories описывают текущее устройство проекта. Файлы-журналы под серию правок («refactoring_X_2026_NN») не заводить: при завершении работы её durable-итог (решения «не переоткрывать», гочи, долг) сразу вносится в постоянные memories — modules/*, conventions, suggested_commands, backlog. Историю «что и когда сделали» хранит git (заголовки коммитов `vXX.Y.Z - тип: описание`). Прецедент: три refactoring-файла серий v29.9–v29.10 расформированы и удалены 2026-07-10.

## Операции

- Переименование/перенос — только `rename_memory` (обновляет `mem:`-ссылки).
- После удаления memory — `serena memories check` на битые ссылки (на Windows нужен `PYTHONIOENCODING=utf-8`).
